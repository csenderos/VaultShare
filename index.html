Guía de Despliegue Real, Gratis y Seguro

Arquitectura: Netlify (Frontend) + Supabase Auth (Roles) + Cloudflare R2 (10 GB Gratis)

¿Por qué no guardar contraseñas ni archivos directamente en Netlify?

Un sitio estático en Netlify entrega todo su código HTML/JS al navegador del usuario. Si pones contraseñas en el código JS, cualquiera que pulse F12 (Inspeccionar) las verá. Además, Netlify limita el tráfico gratis a 15 GB/mes. La solución profesional gratuita separa la interfaz, la autenticación y el almacenamiento:

1 Frontend en Netlify

Sube este único archivo index.html a Netlify Drop o GitHub. Consume menos de 50 KB por visita, por lo que tu cuota de Netlify jamás se agotará.

2 Supabase Auth + RLS

Crea 2 usuarios en Supabase (gratuito). Guarda el inventario de archivos en una tabla Postgres protegida con Row Level Security (RLS) según el rol.

3 Cloudflare R2 (10 GB)

Almacena archivos de hasta 5 TB sin coste de descarga (0 € egress). Una Edge Function genera URLs firmadas (Presigned URLs) válidas por 15 minutos.

Políticas de Seguridad Real (Supabase RLS)

Con estas reglas en tu base de datos, incluso si el segundo usuario intenta manipular el código del navegador, el servidor rechazará cualquier borrado o modificación: 

-- 1. Tabla de inventario de archivos
CREATE TABLE archivos (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  nombre TEXT NOT NULL,
  tamano_bytes BIGINT NOT NULL,
  r2_key TEXT NOT NULL UNIQUE,
  subido_por UUID REFERENCES auth.users(id) NOT NULL,
  es_permanente BOOLEAN DEFAULT false,
  creado_en TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE archivos ENABLE ROW LEVEL SECURITY;

-- 2. AMBOS usuarios pueden ver (SELECT) y subir (INSERT)
CREATE POLICY "Todos ven archivos" ON archivos FOR SELECT TO authenticated USING (true);
CREATE POLICY "Todos suben archivos" ON archivos FOR INSERT TO authenticated WITH CHECK (auth.uid() = subido_por);

-- 3. SOLO TÚ (Admin) puedes modificar (UPDATE) o borrar (DELETE)
CREATE POLICY "Solo Admin actualiza" ON archivos FOR UPDATE TO authenticated 
  USING (auth.jwt() ->> 'email' = 'cristina@tudominio.com');

CREATE POLICY "Solo Admin elimina" ON archivos FOR DELETE TO authenticated 
  USING (auth.jwt() ->> 'email' = 'cristina@tudominio.com');

¿Cómo funciona la subida/descarga pesada sin pasar por Netlify?

  1. El usuario selecciona un archivo de 3 GB en esta web.
  2. La web pide a una Supabase Edge Function un permiso temporal de subida (Presigned PUT URL) para Cloudflare R2.
  3. El navegador envía los 3 GB directamente a Cloudflare R2 (sin límites de tamaño de Netlify ni de Supabase).
  4. Cuando tú pulsa "Eliminar", la función borra el objeto en R2 y el registro en Postgres. El colaborador nunca recibe permisos `DELETE` de R2.
